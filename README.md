# ВашеНазвание — specialty coffee

Статический демонстрационный сайт кофейни с корзиной, отдельным Cloudflare Worker для Telegram и заготовкой интеграции 2GIS. Проект **не использует React/Vite или сервер на хостинге**: сборка копирует статические файлы в `dist/` и подставляет две публичные переменные. Относительные пути позволяют запускать сайт как в корне домена, так и в подпапке репозитория GitHub Pages без настройки `base`. `dist/` включён как пример готовой сборки, но GitHub Actions пересобирает его из исходников.

**Важно:** это концепт. Цены, ассортимент, фотографии и отзывы демонстрационные. Доставка отключена. Юридический текст политики — заглушка: до начала сбора данных подготовьте и разместите полноценные документы с юристом. Заказы, Telegram и карта не будут работать до настройки внешних сервисов. Наличие кода не означает, что они развёрнуты или проверены на реальном аккаунте.

## Структура

- `index.html` — страница; `src/` — стили, интерфейс, единые настройки и каталог.
- `public/images/`, `public/icons/` — изображения и значок; изображения сгенерированы для концепта и не изображают фактические продукты.
- `dist/` — готовые статические файлы после сборки.
- `workers/` — отдельный Cloudflare Worker + Wrangler.
- `.github/workflows/deploy.yml` — официальный workflow Pages.
- `tests/` — локальные тесты Worker с подменой Telegram, без реальной доставки сообщений.

## Локальный запуск

1. Установите Node.js версии 20 или новее с https://nodejs.org/ (в workflow используется Node 22).
2. В каталоге проекта выполните `npm ci`. В проекте нет npm-зависимостей для сайта.
3. Соберите `npm run build` и запустите `npm start`.
4. Откройте `http://localhost:4173/REPOSITORY/` — это проверка работы в подпапке. Также доступен корневой путь `/`.
5. Запустите `npm test`. Если изменили файлы, повторите `npm run build`.

Сборка читает **публичные** переменные из окружения процесса. Для локальной проверки укажите, например, `PUBLIC_API_URL=https://your-worker.workers.dev PUBLIC_2GIS_KEY=your-public-key npm run build`. `.env.example` — справка; файл `.env` автоматически не загружается. Без переменных сайт продолжит работать, но форма сообщит, что сервис не подключён, а карта покажет заглушку.

## Настройки и каталог

Измените `src/config.js`: название (`name`), телефон (`phone`), адрес (`address`), часы (`hours`), ссылки (`telegram`, `instagram`), `coordinates: [долгота, широта]`, опциональный `mapStyleId`. Неподключённые ссылки скрываются. Для публичных ключей используйте переменные сборки ниже; при необходимости можно указать URL Worker и ключ карты в `config.js` как запасные значения. Название и сведения в метаописании/декоративных текстах страницы можно дополнительно отредактировать в `index.html`.

Изменение меню: `src/catalog.js` — единственный каталог для фронтенда **и Worker**. У строки указываются id, название, категория (`coffee`, `signature`, `drinks`, `food`), базовая цена, описание, объёмы через `|`, имя изображения без расширения и бейдж. Добавьте `false` девятым элементом строки, чтобы отключить товар (по умолчанию товар доступен); настройка надбавок — `milkOptions`. Фото находятся в `public/images/`. После изменения каталога **переопубликуйте и сайт, и Worker**, иначе цены и доступность будут отличаться. Все цены в текущем концепте демонстрационные.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub. Загрузите содержимое проекта в его корень, включая скрытую папку `.github/`, и отправьте изменения в ветку `main`.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
3. При каждом `push` в `main` workflow установит зависимости (`npm ci`), выполнит тесты и сборку и опубликует `dist/`. Его также можно запустить вручную: **Actions → Deploy GitHub Pages → Run workflow**.
4. Дождитесь зелёного статуса в Actions. Адрес появится в **Settings → Pages**, обычно `https://USERNAME.github.io/REPOSITORY/`. Для репозитория `USERNAME.github.io` адрес будет корневым.
5. После настройки Worker и 2GIS добавьте публичные переменные в **Settings → Secrets and variables → Actions → Variables** и повторно запустите workflow. Изменение переменных само по себе сайт не пересобирает.

При ошибке проверьте лог Actions, включён ли Pages, существует ли ветка `main` и разрешены ли Actions в репозитории. Workflow использует `checkout`, `configure-pages`, `upload-pages-artifact`, `deploy-pages`, permissions `contents: read`, `pages: write`, `id-token: write` и environment `github-pages`. Отдельная ветка `gh-pages` не нужна.

## Переменные и секреты

| Имя | Где задавать | Назначение |
| --- | --- | --- |
| `PUBLIC_API_URL` | Публичная GitHub Actions Variable / окружение сборки | HTTPS-адрес Worker без `/order`, например `https://coffee-orders.account.workers.dev` |
| `PUBLIC_2GIS_KEY` | Публичная GitHub Actions Variable / окружение сборки | Публичный ключ MapGL, ограниченный разрешёнными доменами в кабинете 2GIS |
| `ALLOWED_ORIGIN` | `[vars]` в `workers/wrangler.toml` | Точный origin сайта без пути и завершающего `/`: например `https://USERNAME.github.io` |
| `BOT_TOKEN` | Только Cloudflare Worker Secret | Токен Telegram-бота |
| `CHAT_ID` | Только Cloudflare Worker Secret | ID чата владельца, получающего заказы |
| `WEBHOOK_SECRET` | Только Cloudflare Worker Secret | Случайная строка для проверки входящего webhook Telegram |

`PUBLIC_*` попадают в клиентский JS и видны всем посетителям. Никогда не помещайте туда токен бота и другие секреты. `ALLOWED_ORIGIN` — CORS-ограничение для браузера, а не аутентификация или полноценная защита от спама.

## Отдельная публикация Telegram Worker

1. Создайте бота через [@BotFather](https://t.me/BotFather), сохраните токен в безопасном месте. Напишите боту `/start` из того чата, куда должны приходить заказы; если это группа, добавьте бота в группу. Получите числовой Chat ID через `getUpdates` **до установки webhook** или проверенным способом в документации Telegram. Не публикуйте токен и ответ `getUpdates`.
2. Установите Wrangler (`npm install -g wrangler`), выполните `wrangler login`. Нужен Cloudflare-аккаунт с поддержкой Durable Objects. При необходимости обновите Wrangler до актуальной версии. Все команды ниже выполняйте из `workers/`.
3. В `wrangler.toml` замените `ALLOWED_ORIGIN` на точный origin вашего сайта (например, `https://USERNAME.github.io`, **без** `/REPOSITORY`). Для локального теста укажите `http://localhost:4173` и разверните отдельно; нельзя одновременно разрешить два origin без доработки.
4. Выполните `wrangler secret put BOT_TOKEN`, `wrangler secret put CHAT_ID` и `wrangler secret put WEBHOOK_SECRET` и вводите значения в запросе CLI. Для webhook используйте случайную строку 1–256 символов из букв, цифр, `_` и `-`; сохраните её для следующего шага. Не записывайте секреты в GitHub, `.env` или `wrangler.toml`.
5. Выполните `wrangler deploy`. Скопируйте HTTPS URL Worker и укажите его в публичной переменной `PUBLIC_API_URL` GitHub Actions. Повторно запустите публикацию Pages.
6. Установите webhook Telegram, передав `https://ВАШ-WORKER.workers.dev/webhook` и тот же `WEBHOOK_SECRET` как `secret_token` в Bot API `setWebhook`. Используйте защищённый способ передачи токена/секрета и не сохраняйте команду в истории терминала. Пример Bash (значения вводятся скрыто):

```bash
read -rs -p 'Bot token: ' TOKEN; echo
read -rs -p 'Webhook secret: ' HOOK_SECRET; echo
read -r -p 'Worker URL (https://...): ' WORKER_URL
curl -sS -X POST "https://api.telegram.org/bot${TOKEN}/setWebhook" \
  --data-urlencode "url=${WORKER_URL%/}/webhook" \
  --data-urlencode "secret_token=${HOOK_SECRET}"
unset TOKEN HOOK_SECRET WORKER_URL
```

Проверьте ответ Telegram `ok: true`. Убедитесь, что лог терминала и история команд не раскрывают токен; при подозрении на утечку немедленно перевыпустите токен через BotFather и обновите секрет. Для полного контроля используйте безопасный HTTP-клиент без записи запросов.

7. Откройте опубликованный сайт, оформите **тестовый** заказ с реальными для теста данными и убедитесь, что сообщение пришло в нужный чат. Проверьте все четыре кнопки: статус должен меняться в сообщении. Проверьте доступ извне и настройки CORS. Тестовые данные затем удалите из чата в соответствии с вашей политикой хранения.

Worker самостоятельно сверяет позиции и цену по каталогу, проверяет данные, ограничивает число запросов и хранит идентификатор/статус в Durable Object; телефон и имя в хранилище не записывает, но они отправляются Telegram. Технические записи заказа удаляются примерно через 30 дней, записи ограничения частоты — примерно через сутки; hash запроса следует считать потенциально чувствительным техническим идентификатором. Дедупликация защищает от повторного использования одного идентификатора. При потере ответа Telegram состояние может быть неопределённым: сайт не покажет успех и предложит связаться с кофейней, чтобы исключить дубликат. Не обещается exactly-once доставка или полная защита от автоматического спама: для рабочего бизнеса добавьте Cloudflare WAF/Turnstile и политику хранения. При смене цен обязательно разверните обе части.

## Карта 2GIS

Получите ключ MapGL на платформе 2GIS, включите нужный API, настройте ограничения ключа по домену. Добавьте `PUBLIC_2GIS_KEY` в GitHub Actions Variables. В `src/config.js` укажите настоящие `address` и `coordinates` в порядке `[долгота, широта]`; возможно указать `mapStyleId`, созданный в редакторе 2GIS. Без координат и ключа показывается понятная заглушка. С корректной конфигурацией карта использует официальный MapGL, маркер и popup; ссылка на маршрут ведёт в 2GIS. Фактическую работу карты необходимо проверить после получения ключа на разрешённом домене.

## Перед запуском для клиентов

- Укажите реальные название, контакты, адрес, часы, координаты, социальные ссылки, ассортимент, наличие и цены.
- Замените иллюстративные изображения и примеры отзывов на реальные разрешённые материалы или удалите их.
- Подготовьте юридически корректную политику и согласие; проверьте ограничения передачи данных в Telegram и сроки хранения.
- Подключите Worker, бота и webhook; проверьте реальные доставку и статусы, ошибки и защиту от злоупотреблений.
- Подключите MapGL и проверьте маркер, popup и маршрут на реальном домене.
- Сервис доставки в текущем виде недоступен. Оплата, управление наличием и полноценная система заказов/CRM не реализованы.
